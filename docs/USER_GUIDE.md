# EnvNexus AI 使用说明

## 1. 首次启动与扫描

启动后 App 不会自动扫描。若存在 `<data-root>\cache\last-environment-scan.json`，App 只显示上次手动扫描结果；没有快照时显示“尚未扫描”。只有点击“开始扫描”或“重新扫描”才会执行下列只读检查并覆盖快照：

- 查询 `where` 命令解析顺序；
- 运行工具自身的版本命令；
- 读取与开发工具有关的用户级、系统级环境变量；
- 检查 pyenv-win、NVM for Windows、fnm、Volta、rustup、Jabba、goenv、rbenv、Uru、JDK 相邻目录和 Android SDK 子目录；
- 识别 EnvNexus AI 安装清单；
- 报告重复、失效、相对或空 PATH 条目，以及变量跨作用域冲突。

扫描不会写环境变量、移动目录或卸载软件。安装、切换、修复、卸载或恢复操作完成后，当前快照会标记为“环境已变更”；App 不会自动重扫，需由用户决定何时更新结果。

## 2. 查询与安装

1. 打开“工具链”；
2. 点击目标工具卡片，进入该工具的独立管理页；
3. 在页面上方点击“选择目录”，设置该工具的默认安装根目录；
4. 点击“查询官方源”；
5. 选择版本并点击“安装”；
6. 阅读下载主机、校验策略、目标路径和步骤；
7. 点击“确认并执行”。

目录选择结果会持久化到 `<data-root>\config\tool-roots.json`，关闭 App 或重启电脑后仍然保留。普通工具分别保存自己的目录；Android 组内的 JDK、SDK、NDK、Gradle、CMake、ADB 始终同步为同一个根目录。

非 Android 工具默认目录为：

```text
<选择根目录>\<tool-id>\<version>
```

Android 组件使用同一个根目录：

```text
<Android根>\cmdline-tools\latest
<Android根>\platform-tools
<Android根>\ndk\<version>
```

Android 不再是单独的侧边栏模块；它作为“Android 构建工具链”分组显示在“工具链”页面中，每个 Android 工具仍有自己的独立管理页。

下载先写入 `.part`，支持服务端 Range 时继续传输。完成后验证官方校验值，再安全解压到同盘暂存目录，验证版本命令后提交。

## 2.1 CMD 与 PowerShell 管理命令

侧边栏“命令说明”位于“设置”上方。页面为每个工具生成一组 `<工具>-<操作>.cmd`，默认放在 `<data-root>\commands`。可直接输入绝对路径，或点击“浏览”选择其他保存目录，再点击“保存目录”。保存目录只更新 App 配置并创建目录，不修改 PATH。

若当前命令目录已经加入用户 PATH，必须先在页面中生成停用计划并确认，才能更换目录，以免两个目录内的同名命令同时生效。重新启用时仍会显示用户 PATH 差异、备份、冲突和确认计划。

点击“生成并启用命令”时，App 会先生成脚本，再显示把命令目录加入 HKCU 用户 PATH 的差异、冲突、备份和恢复步骤。只有确认计划后才写入；不会修改系统 PATH。确认后关闭并重新打开 CMD 或 PowerShell。

常用只读命令：

```powershell
env-tools
jdk-list
python-list
android-sdk-list
env-diagnose
env-repair "PATH_DUPLICATE_用户"
jdk-versions
```

- `env-tools` 无需扫描即可列出 15 个内置工具及已保存的安装根目录。
- `<tool>-list` 只读取上次快照；没有快照时返回“尚未扫描”，不会执行隐式扫描。
- 工具前缀包括 `python`、`jdk`、`go`、`rust`、`node`、`git`、`maven`、`dotnet`、`ruby`、`php`、`android-sdk`、`android-ndk`、`gradle`、`cmake`、`adb`。
- 只有显式执行 `env-scan` 才会扫描 PATH、版本管理器、受管清单和当前保存的工具根目录，并覆盖桌面 App 与命令脚本共用的 `<data-root>\cache\last-environment-scan.json`。
- CMD 脚本中不保存工具安装目录。即使先生成脚本、之后再选择工具目录，`*-root get` 和 `*-install` 也会读取最新配置。
- `*-list` 只读取上次扫描快照；修改目录或在目录中手动增删版本后，需显式运行 `env-scan` 才会刷新版本与路径。
- 所有命令都可追加 `--json`，便于 PowerShell 脚本或其他程序解析。

目录与管理操作：

```powershell
jdk-root get
jdk-root set "E:\DevTools\Java"
env-scan
jdk-install 21.0.8
jdk-use "E:\DevTools\Java\java\21.0.8"
jdk-repair "E:\DevTools\Java\java\21.0.8"
jdk-uninstall "E:\DevTools\Java\java\21.0.8"
```

`install`、`use`、`repair` 和 `uninstall` 默认只生成计划并显示环境差异，不执行变更。核对后在原命令末尾添加 `--yes` 才会确认执行，例如：

```powershell
jdk-use "E:\DevTools\Java\java\21.0.8" --yes
```

Android 组中任一工具执行 `*-root set` 时，会同步 SDK、NDK、JDK、Gradle、CMake、ADB 的共享根目录。目录必须是绝对路径且不能是磁盘根目录。便携版移动或主程序路径改变后，应在“命令说明”页点击“重新生成 / 修复脚本”。

## 3. 升级与多版本

升级采用“安装新版本并保留旧版，再切换默认版本”的方式，避免覆盖后无法回退：

1. 安装目标新版本；
2. 在“本机版本”中点击新版本的“切换”；
3. 确认环境差异；
4. 打开新终端验证；
5. 确认无误后再卸载旧的 EnvNexus AI 受管版本。

## 4. 切换默认版本

切换计划会展示：

- 用户 PATH 添加与删除项；
- `JAVA_HOME`、`GOROOT`、`CARGO_HOME`、`RUSTUP_HOME`、`MAVEN_HOME`、`DOTNET_ROOT`、`RUBY_HOME`、`PHP_HOME`、Android 变量等变化；
- 系统 PATH 是否会遮蔽目标版本；
- 是否需要系统级权限。

确认后，App 先备份完整 HKCU 用户环境，再写入、回读校验并广播环境变化。已打开的终端不会改变，请打开新终端运行版本命令验证。

若系统 PATH 中同名工具优先级更高，计划会被阻止。MVP 不会要求管理员权限或自动修改系统 PATH。

## 5. 修复与卸载

“修复”和“卸载”只对带有效 `.envpilot-install.json` 的 EnvNexus AI 受管版本开放。

- 修复：重新查询同版本官方文件，下载并验证新暂存版本；旧目录先隔离，新版本验证失败则恢复旧目录。
- 卸载：预览并备份仍指向该版本的用户 PATH/工具变量，先清理环境引用，再隔离和删除受管目录；目录删除失败时尝试恢复用户环境。
- 外部安装：只检测、切换和诊断，不递归删除未知目录。

## 6. 环境备份恢复

打开“变更中心”，刷新备份列表，选择备份并生成恢复计划。恢复只覆盖 HKCU 用户环境，不修改系统变量；恢复前还会再次备份当前状态。

备份位于：

```text
<data-root>\backups\environment
```

## 7. 诊断与版本管理器

“诊断与日志”页面同时显示全局环境问题、工具问题和已识别的版本管理器。

- 本地规则引擎始终可用，不要求填写 API Key。点击“本地分析与建议”可查看原因证据、本机架构与目录因素、修复建议和可复制的 CMD/PowerShell 命令。
- 本地规则会综合已安装版本、当前默认版本、`where.exe` 解析顺序、用户/系统 PATH、标准工具变量，以及 pyenv、NVM、fnm、Volta、rustup 等版本管理器。若同一工具同时由多个管理器接管，或管理器 shim 与外部安装互相遮蔽，会单独报告。
- 对名称含工具标识且值为绝对目录的非标准变量也会做保守检查，例如 `RUST1=E:\Rust\1.80` 与 `RUST2=E:\Rust\1.90`。EnvNexus AI 会解释它们可能是用户有意保留的别名，不会擅自删除或合并。
- 用户 PATH 的重复、失效、空项或相对条目可生成修复计划。计划只修改 HKCU 用户环境，并显示逐项差异、保护的版本管理器路径、备份和回滚方式；仍需再次确认才能执行。
- 用户级与系统级变量值完全相同时，可生成删除重复用户变量的计划；值不同时不会替用户决定。
- 系统 PATH、HKLM 或需要管理员权限的问题不会提供自动修复，避免未经确认修改系统级配置。
- 诊断弹窗内的命令可逐条复制。`env-repair "<诊断代码>"` 只预览计划，追加 `--yes` 才确认执行；GUI 的“一键修复”同样先打开计划预览，不会跳过确认。
- 工具自身问题可点击“打开工具详情”，进入对应工具的独立页面处理。
- “导出完整报告”会保存扫描快照、本机上下文和每条问题的本地分析/命令，便于离线排查或交给他人复核。

修复完成后请打开新终端验证，并手动点击“重新扫描”更新快照。

## 8. AI 分析

在“设置 → AI 分析与修复建议”中选择厂商，填写 API 基础 URL 和 API Key，保存后点击“远程获取模型”，再从下拉框选择模型。内置入口包括 OpenAI、Anthropic/Claude、Kimi、DeepSeek、智谱 GLM、xAI/Grok、阿里云百炼/Qwen、Google Gemini 和第三方兼容服务；厂商卡片、配置标题和托盘菜单均显示对应品牌图形。

部分厂商或第三方网关不提供模型列表接口，此时可在同一区域手动填写官方模型 ID。Qwen 等区域/工作空间端点可能不同，基础 URL 可编辑。

每个厂商独立保存，编辑 OpenAI 不会覆盖 DeepSeek、Claude 或其他厂商：

- URL、协议和已选模型：`<data-root>\config\ai\providers\<provider>.json`；
- API Key：由当前 Windows 用户的 DPAPI 分别加密到 `<data-root>\config\ai\secrets\<provider>.dpapi.json`；
- 当前使用的厂商：`<data-root>\config\ai\active-provider.json`。

保存厂商配置或选择模型不会自动切换当前厂商。配置同时具备 API Key 和模型后，可点击“设为当前 AI”，也可从托盘“AI 服务”菜单切换；当前厂商会明确标记。旧版聚合配置在首次读取时会迁移到上述独立文件，旧文件保留作为迁移依据，但后续不再参与覆盖。

前端不会读回 API Key 明文。App 启动和扫描时不会连接 AI。只有在某条诊断上点击“AI 增强分析”并再次确认后，才会发送该条诊断、相关已安装版本与路径、版本管理器、本机架构以及本地规则已得出的原因和建议。API Key 不进入提示词。

AI 用来补充与当前电脑相关的解释和解决顺序；未配置或调用失败时，本地分析仍然完整可用。AI 结果没有执行权限，也不会被转换成任意命令或注册表写入；可执行操作仍必须由本地确定性规则生成，并经过差异预览、备份、确认和回滚流程。

## 9. 窗口与系统托盘

在“设置 → 应用与启动”中可以配置：

- 点击关闭按钮时直接退出程序，或只隐藏窗口并继续在系统托盘运行；
- 启动 EnvNexus AI 后是否立即隐藏到托盘；
- 登录当前 Windows 用户后是否自动启动 EnvNexus AI；
- 界面和托盘使用简体中文、繁体中文、English、日本語或한국어；
- 点击“隐藏到托盘”立即隐藏当前窗口。

为避免用户误以为程序已经退出，默认关闭行为仍是“直接退出程序”，两个启动选项默认关闭。设置保存到 `<data-root>\config\app-preferences.json`。保存“登录 Windows 后自动启动”时，App 才会写入或删除当前用户的 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run\EnvNexus AI`，不需要管理员权限，也不会写系统级启动项。语言与关闭行为保存后立即生效；“启动后隐藏到托盘”在下次启动生效。

EnvNexus AI 的图形界面采用单实例运行。已经打开时再次双击同一程序，第二个进程会退出，原窗口会取消最小化、从托盘恢复并获得焦点。`jdk-list`、`env-tools` 等带参数命令在进入 GUI 前执行，因此不会被正在运行的桌面实例拦截。

App 会记住最后停留的总览、工具链、变更中心、诊断、命令说明、设置或具体工具详情页，并保留设置页最后选择的 AI 厂商。下次打开时恢复该位置；升级后如果页面 ID 失效则回到总览，如果工具详情缺少有效工具 ID 则回到工具链。第二次双击唤醒现有窗口时不强制改变当前页面。

EnvNexus AI 运行时会显示 Windows 系统托盘图标：

- 双击托盘图标：打开总览；
- 右键菜单的常用操作与每个工具前都有对应图标；
- “工具链”二级菜单列出 15 个工具，点击工具内的“打开管理页”会恢复 App 并进入该工具的独立配置页；
- 每个工具的“已安装版本”三级菜单来自上一次手动扫描快照；默认版本会标记且不可重复选择，点击其他版本会打开 App 中现有的默认版本切换计划；
- 版本菜单点击不会静默切换：仍需查看 PATH/变量差异、冲突、备份和回滚说明，再明确确认；
- 扫描快照存在问题时，“诊断管理”二级菜单逐项列出诊断；每个问题的三级菜单可打开本地诊断详情，确定且标记为可修复的项目还可生成修复计划；
- “AI 服务”二级菜单只列出已经保存 API Key 且已选择模型的有效厂商；当前厂商带勾且不可重复选择，点击其他厂商会直接切换后刷新菜单；
- 不可自动修复的诊断会显示“查看建议后人工处理”，不会为了提供托盘按钮而放宽系统级配置、自定义别名或多版本管理器的安全边界；
- 从未扫描时，工具和目录管理入口仍然存在，但版本层级显示“尚未扫描”；打开托盘菜单本身不会扫描；
- “手动重新扫描”属于用户明确触发的扫描；普通启动、启动后隐藏、打开托盘菜单或恢复窗口都不会扫描；
- 选择“退出 EnvNexus AI”会终止进程，不受“关闭按钮最小化到托盘”设置影响。

语言切换覆盖导航、设置、常用按钮与托盘操作。工具名、版本号、文件路径、诊断证据和可复制命令保持原文，避免翻译改变可执行内容。

工具图形从项目内置 SVG/PNG 读取，不在运行时访问 CDN。Java 使用彩色咖啡杯标识；其余工具优先使用对应品牌识别图形。Android SDK、NDK 和 ADB 共用 Android 品牌图形，并在 App 内附加包、CPU 或终端角标区分用途。

## 10. 主题

在“设置”中选择：

- 现代科技：深海军蓝数据网格、薄荷青 HUD 线框、切角面板和环形数据仪表；
- 赛博朋克：紫色基底、品红与黄色霓虹、扫描线和切角；
- 日系轻量：浅色、低对比度、柔和留白；
- 游戏 HUD：黑色底、橙色霓虹、蜂窝描边、六边形仪表、切角面板和发光操作按钮；
- 专业极简：中性灰白、克制阴影和办公软件式层级。

主题 ID 和最后界面状态保存在 WebView localStorage，只影响显示和下次打开位置，不触发扫描或环境修改。

所有主页面右侧都有可见滚动条，可直接使用鼠标滚轮。工具独立管理页中的长版本列表与页面一起纵向滚动。

## 11. 数据目录

正式版默认在可执行文件旁创建 `EnvNexusAIData`。设置页可以选择其他目录，保存后重启生效；旧数据不会自动迁移。选择目录只写一个安装目录旁的 `envnexus-ai-data-root.json` 指针，不修改系统环境变量。升级时，如果新目录或新指针不存在，程序会继续读取旧的 `EnvPilotData` 或 `envpilot-data-root.json`。

自动化运行可设置：

```powershell
$env:ENVNEXUS_AI_DATA_ROOT = "E:\EnvNexusAIData"
```

该变量优先于设置文件；旧变量 `ENVPILOT_DATA_ROOT` 仍可兼容读取。

## 12. 日志与排障

```text
<data-root>\logs\operations-YYYY-MM.jsonl
<data-root>\transactions\<operation-id>.json
```

遇到失败时保留错误原文、操作 ID、目标路径和 journal。不要手工删除仍处于 `.envpilot-staging-*`、`.envpilot-repair-backup-*` 或 `.envpilot-uninstall-*` 的目录，先核对日志和安装清单。
