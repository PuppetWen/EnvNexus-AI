# 已知限制

以下是 EnvNexus AI 0.1.0 MVP 的明确边界，不作为已完成能力描述：

1. 仅构建和验证 Windows x64 MSVC 版本；没有 ARM64 包。
2. 不执行系统级环境变量、HKLM 或系统 PATH 修改。系统 PATH 遮蔽时切换计划会阻止执行。
3. 崩溃或断电后会保留安装 journal 和暂存/隔离目录，但尚无自动恢复向导；普通错误返回路径已实现回滚。
4. 官方版本清单当前不做 ETag/离线缓存；网络不可用时需要稍后重试。已下载发行包有本地缓存，并在复用前重新校验。
5. “升级”由安装新版本、切换、验证、再卸载旧版本组成，尚未合并为一个跨步骤原子计划。
6. 本次真实安装端到端测试使用 Python 3.13.14 官方嵌入包。其余工具没有在开发机上逐一下载大型发行包并实际安装；Maven、.NET SDK、Ruby、PHP 已单独完成实时官方源测试。
7. 外部安装只做发现、诊断和默认版本切换；EnvNexus AI 不直接调用厂商卸载器，也不会删除没有 EnvNexus AI 清单的目录。
8. 部分官方 API 不提供可用校验值时，计划会显示供应链警告而不是伪造哈希；用户仍需确认。正式企业策略可改为“无哈希一律拒绝”。
9. 数据目录更改在重启后生效，不自动迁移旧配置、缓存、日志或下载。
10. 外部 rustup 工具链的默认切换目前采用用户 PATH；EnvNexus AI 受管 Rust 使用隔离的 `CARGO_HOME`/`RUSTUP_HOME`。不会改写全局 rustup default。
11. 当前没有应用自动更新、代理凭据 UI、下载并发设置、代码签名或企业策略模板。
12. 本次开发没有执行真实 HKCU 环境写入，以免改变用户现有环境；写入、回读、回滚代码已编译并由纯函数/边界测试覆盖，最终交互确认仍需用户自行验收。
13. 没有使用用户的真实 OpenAI、Claude、Kimi、DeepSeek、GLM、Grok、Qwen 或 Gemini 凭据执行在线模型列表和推理测试；已验证协议适配、响应解析、URL 限制与 Windows DPAPI 往返，但真实账号权限、区域端点和计费需用户自行验证。
14. 某些厂商或兼容网关没有 `/models`、仅向特定工作空间开放，或返回非标准格式。UI 提供可编辑基础 URL 和手动模型 ID；这不等同于所有第三方服务都已兼容。
15. AI 增强分析只生成文本建议，不会自动执行模型建议，也不会把模型输出转换成环境修改计划。确定性的一键修复来自本地规则，只覆盖用户级、结果唯一且可备份回滚的问题；自定义别名、多版本管理器取舍和系统级问题仍需用户判断。
16. 工具命令脚本记录当前 `EnvNexus-AI.exe` 的绝对路径。移动便携版后必须在“命令说明”页重新生成脚本。命令目录可由用户选择，但不会自动加入 PATH；用户需先核对 HKCU PATH 差异并确认。
17. EnvNexus AI 当前把每个 .NET SDK ZIP 解压到独立版本目录，以便原子回滚、切换和卸载。多个版本可以共存，但选中的 `dotnet.exe --list-sdks` 只看到该隔离目录中的 SDK；它不是微软“多个 SDK 合并到同一 DOTNET_ROOT”布局，项目通过 `global.json` 自动选择另一个 EnvNexus AI 隔离版本前仍需先切换默认目录。
18. 2026-07-23 的完整 15 源聚合复测被 `go.dev` 连续连接超时阻断；同次新增的 Maven、.NET SDK、Ruby、PHP 四源测试通过。网络或上游波动不被记为通过。
19. 五种语言目前覆盖导航、设置、常用操作与托盘菜单；工具名、官方版本信息、路径、诊断证据和可复制命令保留原文，以避免机器翻译改变技术含义或命令内容。
20. 工具图形用于产品识别，不表示 Python、Eclipse Adoptium、Google、Microsoft 或其他商标所有者对 EnvNexus AI 的认可。Android SDK、NDK 和 ADB 在 16–32 像素菜单尺寸下复用 Android 图形，App 内使用用途角标区分。
